#ЛАБ 3

**Ошибка 1.**
Свойство объявлено как `public int Health { get; set; }`: доступ на запись открыт
внешнему коду, поэтому строка `alexander.Health = -100;` в Program.cs компилируется
и портит состояние героя, обходя все методы. Это нарушает инкапсуляцию
Исправление — закрыть запись: `public int Health { get; private set; }`.
После этого та же строка не компилируется (ошибка CS0272: недоступный setter).


**Ошибка 2**
В конце setter свойства `Name` было написано:

csharp
value.Trim();
_name = value;

## самостоятельный проект

- Rating, PlayHours и остальные данные хранятся в свойствах с private set,
  прямая запись снаружи запрещена.
- Проверка рейтинга находится в UpdateRating: значения вне диапазона 0–10 игнорируются.
- Проверка часов — в AddPlayHours: нулевое и отрицательное значение игнорируются.
- Конструктор ставит Rating = 0.0 и PlayHours = 0 — начальные значения всегда допустимы.
- При попытке записать рейтинг напрямую (witcher.Rating = 11;) проект не
  компилируется (CS0272); при вызове `UpdateRating(25.0) рейтинг остаётся прежним (8.7).

## ответы на вопросы
1. Запрет внешней записи (private set) отвечает только на вопрос «кто может записывать»: из Program.cs строка alexander.Health = -100; не компилируется (CS0272). Но он не отвечает на вопрос «что именно записывается»: конструктор и методы находятся внутри Hero, поэтому им запись доступна без ограничений. Проверку допустимого числа это не заменяет. Поэтому:
здоровье при создании проверяется в конструкторе Hero(string name, int health): сначала готовится MaxHealth (если health <= 0 — предел 100, если health > 200 — предел обрезается до 200), затем Health приводится к диапазону от 0 до предела;
здоровье при изменении проверяется в методах: TakeDamage держит нижнюю границу (Health < 0 → 0), Heal — верхнюю (не поднимает выше MaxHealth) и отбрасывает неположительное лечение.
2. Строка Name = name; в конструкторе — это присваивание не полю, а свойству: оно вызывает его set. Аргумент конструктора name попадает в параметр value внутри setter. Там строка проходит проверку string.IsNullOrWhiteSpace(value) — при пустой записи в _name кладётся «Безымянный герой» — и очищается от пробелов: _name = value.Trim();. Итоговая цепочка: аргумент name → Name = name → value → проверка → закрытое поле _name. Именно поэтому пробелы из "   Александр   " убираются один раз, в классе, а не в каждом месте вызова.

3. создание new Hero("Проверка нижней границы", -100) → 0/100 — нижняя граница не нарушена, сработало запасное правило конструктора;
создание new Hero("Проверка верхней границы", 5000) → 200/200 — верхняя граница;
alexander.TakeDamage(30); alexander.Heal(10); → 130 — обычное изменение внутри диапазона;
alexander.Heal(5000); → 150 — лечение остановилось ровно на пределе MaxHealth, а не ушло выше;
alexander.TakeDamage(5000); → 0; жив: False — урон остановился на нуле, не ушёл в минус;
Heal(-20) → 150 — недопустимый вызов ничего не изменил;
у Артёма всё время 120/120 — вызовы Александру не затронули другой объект.
